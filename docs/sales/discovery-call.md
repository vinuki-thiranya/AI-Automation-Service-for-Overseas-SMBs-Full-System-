# Discovery call (20 minutes)

From spec §6.2, as a run sheet. Book it through the website's contact page (Cal.com once it's set up). Take notes straight into a copy of `docs/delivery/rehearsal/bayside-requirements.txt` format, one requirement per line, so `scripts/scope-check.ts` can read them afterwards.

| Minutes | Ask | Listen for |
|---|---|---|
| 0–2 | "Thanks for the time. I'll ask a few questions, then tell you honestly whether this fits." | |
| 2–7 | How do enquiries reach you today, and who answers them? | Channels (phone, WhatsApp, website, Facebook), who's on the desk, lunch and after-hours gaps |
| 7–10 | How many do you miss or answer late each week? What is one new patient worth to you? | Their numbers. These go in the proposal and the website calculator |
| 10–13 | What do you already use: calendar or practice system, phones, CRM? | Cliniko / Google Calendar / Jane (link-out only), phone provider for missed calls |
| 13–16 | If this worked perfectly, what would you see in 30 days? | Their success measure: put it in the proposal's first line |
| 16–18 | Who else decides? What budget range feels reasonable? | The owner vs the practice manager; whether a care plan is acceptable |
| 18–20 | Close: "I'll send a one-page plan and price tomorrow. If it fits, we start next Monday." | |

**Show, don't tell:** if there's time, share your screen and message the demo clinic (the try-it chat on the website, or the demo number once it exists).

**Don't:** promise results in numbers, quote prices outside the price list, or agree to anything `scope-check.ts` would flag without saying it's extra.

**Afterwards (same day):** run the scope check on your notes, fill in `proposal-template.md`, add the prospect to the pipeline sheet as "Discovery done", and set reminders for day 3 and day 7 (spec §6.1).
